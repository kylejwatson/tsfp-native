# TimeSplitters: Future Perfect — static recompilation (working notes)

Native Windows build of TS:FP (Xbox, title 0x45410066, XDK 5849, entry 0x0038024D),
lifted to C by the xboxrecomp toolkit. Read `xboxrecomp/CLAUDE.md` too: it is the
toolkit's own context (architecture, debug table, env switches) and is not repeated here.

## Build / lift / run

- **Linux** (this machine is now CachyOS; same checkout): `./build.sh` -> `build-linux/futureperfect_recomp` (clang + Ninja, ~30 s full build of the lifted code). `./play.sh [route]`, `./record.sh <name>`, `./run_seq.sh` and `./relift.sh` (python3) all work. See "Linux port" below.
- Build (Windows): `cmd.exe //c "C:\Users\mail\Documents\mygame\build_vs.bat"` (the bare name stopped resolving from Git Bash) (VS 2026 "18" + Ninja; writes `build/futureperfect_recomp.exe`). ~10 min full, seconds incremental. Builds are long: run in background and poll `tasklist` for ninja/cl.
- Re-lift: `./relift.sh` (from disasm; needed after seed changes). `FROM=lift ./relift.sh` after adding/removing an `HLE_EXPORT` in `xboxrecomp/src/hle` or a function in `recomp_manual.c`.
- The exe finds the game at `..\game_files` relative to itself (or `RECOMP_GAME_DIR`).
- Scripted test run with frame dumps + contact sheet: `./run_seq.sh <name> "<RECOMP_INPUT_SEQ>" <seconds> [dump_every]` → `runs/<name>/montage.png`, log `runs/<name>.log` (`runs/` is ignored; put captures in `caps*/`, replays in `rep*/`, also ignored). `MINDRAWS=n` and `EXTRA="ENV=1 ..."` are honoured. Always muted.
- Input sequences (needs an existing profile in `game_files/UDATA`, i.e. "Player 1" at index 1):
  - story level 1 (gameplay in ~40 s): `14000:a,17000:down+a,20000:a,23000:a,26000:a,29000:a,36000:start` (the `start` skips the cutscene; a second `start` pauses)
  - arcade game-type menu: `14000:a,17000:down+a,21000:down,22500:a,26000:a`
- The same routes as files: `RECOMP_INPUT_SEQ=@../seqs/brain_drain.seq` (`story1`, `arcade_select`). Scripts can move the mouse (`mouse_right:1000` = 1000 counts = 55 degrees at sensitivity 2.5). `RECOMP_INPUT_RECORD=<file>` / `RECOMP_INPUT_REPLAY=<file>` record and replay port 1 (pad and mouse).
- Your recordings (`recordings/`, ignored): `quick-story1`, `quick-brain-drain` (fast routes into gameplay), `video-settings`, `control-settings`. Replays are wall-clock timed, so the title screen sometimes eats a press and the route drifts; scripted settings tests change the Player 1 profile's options.
- Input is ignored while the window is unfocused (our change); `RECOMP_INPUT_SEQ` is unaffected. Keyboard: Z=A, X=B, arrows, Enter=Start.
- Scripted runs: pass `RECOMP_MOUSE=0` (run_seq.sh does) or the window captures the desktop cursor when it comes up in front.

## Debugging tools that paid off

- Frame capture + offline replay: `RECOMP_D3D8_CAPTURE=caps/c.d3dcap RECOMP_D3D8_CAPTURE_SWAP=3000 RECOMP_D3D8_CAPTURE_EVERY=400 RECOMP_D3D8_CAPTURE_MINDRAWS=50`, then `build/xboxrecomp/src/replay/d3d8_replay.exe caps/c_N.d3dcap --out rep/x_` (`--list-draws`, `--no-combiners`, `--skip-draw n`). With `RECOMP_D3D8_PS_SHOW=t0|v0|r0|fog|foga|fogon` to view one combiner register, `RECOMP_D3D8_PS_DUMP=1` for HLSL (+ raw final-combiner words). `xboxrecomp/scripts/bmp_to_png.py` to view BMPs.
- `RECOMP_HLE_D3D8_DECL_DUMP=1` (vertex declarations, stride-skip details), `RECOMP_HLE_D3D8_PUSH_DUMP=1` (methods in the push buffer), `RECOMP_AUDIO_DUMP=<dir>` (raw PCM per host voice), `RECOMP_DSOUND_STREAM_RATE=<Hz>` (force stream rate).
- `RECOMP_FPS_WATCH=<guest addr>` prints a guest dword and its rate in every `[FPS]` report (FP's game clock: `0x7497B0`). `RECOMP_RAM_DUMP=<dir> RECOMP_RAM_DUMP_AT=<s>,<s>` writes guest RAM at those times for offline diffing. `RECOMP_HLE_D3D8_TRACE_SWAPS=a-b` shows Clear flags and render-target switches per frame; the replay's `--list-draws` prints clears with their rects.
- Moments reached by playing (`play.bat` style, no script): with `RECOMP_RAM_DUMP=<dir>`, **F7** writes the next 8 frames (`RECOMP_RAM_DUMP_BURST`) as `ram_k<n>_<i>.bin`/`contig_k<n>_<i>.bin`, which catches a value that flips between frames; `RECOMP_WATCH_ARM_KEY=1` holds `RECOMP_WATCH_WRITE` until **F6**. Objects allocated at a level load had the same address in every run (Ash `0x8265D598`, his seat record `0x82696808`). Character objects: position `+0x64` (x,y,z), heading `+0x70`, flags `+0x08`, handle `+0x2C`, data `+0x7C` (whose first word points back).
- The `[HLE-D3D8] shadow: ... skipped ...` stats line is the first thing to read for rendering problems.
- Finding game state: `RECOMP_RAM_DUMP` writes `ram_<s>.bin` (low 64 MB) **and `contig_<s>.bin` (0x80000000..)** -- the player object is in the contiguous window, so diff both. Read-watching a value (`RECOMP_WATCH_WRITE=<addr> RECOMP_WATCH_READS=1 RECOMP_WATCH_ARM_ON=lv60.pak`) names who reads it; that is how the look code was found from the pad record. Ghidra's xrefs miss calls through tail-jump thunks (`player_control_axis` jumps to `pad_axis`).
- Unresolved `[ICALL]` target → `py -3 -m tools.seed_from_log <log> ../game_files/default.xbe --functions ../.pipeline/disasm/functions.json --seeds ../config/seeds.json` (from `xboxrecomp/`), keep only new entries, `./relift.sh`.

## What has been fixed (and why) — details in git log

1. Level-load crash: unseeded function 0x5FCF0; MSVC `memcpy` (sub_000245C0) jumps into its own middle → native override in `recomp_manual.c`.
2. No 3D geometry: FP writes its NV2A vertex arrays itself (sub_0001EB00 via BeginPush/EndPush, one array per attribute). `hle_d3d8_push.c` follows the push buffer and gathers those arrays into the declaration layout when the stream-0 view can't hold the vertex.
3. Sepia world: FP's final combiner is `fog.a, fog.rgb, r0` (0x13030C00), opposite to the XDK default; fog-disabled now means "no fog" for either lerp form (`d3d8_combiners.c`).
4. Green/yellow icons: L8/A8L8/AL8/L16 textures are expanded to BGRA (L,L,L,A) at upload (`d3d8_resources.c`).
5. Background input: keyboard/pad gated on window focus (`input_bindings.c`).
6. Audio too fast/high: streams are created at 44.1 kHz but FP calls `IDirectSoundStream_SetFormat` per file (menu music 32 kHz stereo, level audio 22042 Hz). `CDirectSoundStream_SetFormat` is now replaced (`hle_dsound_stream.c`, `[DSOUND] ... SetFormat:` log lines).
7. Vertex constants written straight into the push buffer (0x1EA4 load + 0x0B80 data, ~4M registers/min in level 1) are replayed to the host by the push walker (`hle_d3d8_push.c`), and the walk now runs before *every* shadow draw (`shadow_sync_push` in `hle_d3d8.c`), not only at EndPush.
8. Keyboard sticks: `config/input_bindings.json`, copied beside the exe (`build/input_bindings.json`); the exe now also looks beside itself, not just the working directory. WASD = left stick, IJKL = right stick, E/Space = A, F = B, R = X, Q = Y, P = White, Tab = Black, LShift = left stick click, middle mouse = right stick click (triggers are mouse buttons only, see 18). (A copy written to `%APPDATA%` from a Claude shell did not reach the user's real profile.)
9. Stale audio: FP stops streams with Pause + `FlushEx` (not intercepted before), so old packets played after the next resume. `CDirectSoundStream_FlushEx` is replaced. `RECOMP_DSOUND_TRACE=1` logs every stream call with timestamps.
10. Blown-out particles (space smoke, dust): NV2A `EXP`/`LOG` are expp/logp (four different components); the translator returned `exp2(x)` everywhere. FP's particle program uses `EXP.y` as frac() for a spin angle. Fixed in `d3d8_vsh.c` and the CPU interpreter `kernel/nv2a_vsh.c`.
11. Dust storm covering the level ("sepia"): vertex programs output `float4 oT0..3` but both pixel shaders take `float3` texcoords with `float fog` packed into TEXCOORD3's `.w`, so every program draw read its fog from `oT3.w` (a constant ~3 → fully fogged). Program VS_OUT texcoords are float3 now.

12. No sound effects (menu clicks, guns, damage): XDK 5849 moved the DirectSound buffer settings 4 bytes later (data +0xBC, size +0xC0, loop +0xCC/+0xD0; read from the game's own `CDirectSoundBufferSettings_SetBufferData`/`SetLoopRegion`). With the 5344 offsets every ADPCM buffer's "size" was a pointer, so none got a model. `hle_dsound.c` now reads the DSOUND build from the XBE header's library table (`[DSOUND] library build 5849: buffer settings at +0xBC`).
13. Push-buffer gather (`hle_d3d8_push.c`) is used whenever a declared attribute's NV2A array is not where the stream 0 view says, not only when the stride is too small.
14. Unfed vertex attributes: NV2A leaves each enabled attribute's current value at the last vertex a draw fetched (xemu models it the same way); the host left them at (0,0,0,1). FP's programs take colour from v2 and many draws feed no v2, so visors/glows were black blobs and whole character bodies were missing. `hle_d3d8_push_after_draw` now forwards those values; the walker also decodes `SET_VERTEX_DATA*`. Side effect seen once: a bright rectangle in the first fade-in frame of level 1.

15. Characters in pieces, grey first-person shotgun, missing character-select models: FP loads its skinning programs into the NV2A program slots by writing the push buffer itself (`0x1E9C`/`0x0B00`/`0x1EA0`), so the host drew palette-skinned vertices (v0 = bone offset -24/-28/-32) with the last XDK-selected rigid program. The walker mirrors program memory and `shadow_sync_program` (`hle_d3d8.c`) binds the push buffer's program before each draw (`RECOMP_HLE_D3D8_PUSH_PROGRAM=0` to disable).

16. Cutscenes/dialogue out of sync, game ~20% fast: this is the **PAL** disc (French/German/Italian/Spanish paks; certificate region rest-of-world), so the kernel reports a PAL-I console and FP asked `CreateDevice` for 50 Hz, but the vblank clock was fixed at 60 Hz. FP's game clock is a counter its vertical-blank callback bumps (`sub_00022020` → `0x563918`; per-frame step capped at 3 in `sub_001538C0`, accumulated at `0x7497B0`). The level-1 intro track (musicts.pak entry 0) is 122 s and the picture was over at 100 s. Now: the vblank follows the refresh `CreateDevice` asks for (`xbox_SetVblankRate`), and a PAL console advertises PAL60 (`RECOMP_PAL60=1` default; EEPROM `XC_VIDEO` 60 Hz flag + the AV pack's 60 Hz refresh bit), so FP runs 60 Hz at the right speed. Intro now lasts 120 s.
17. Black screen behind control hints (cat racing, level 1's "To change controls…") and black main-menu backgrounds: FP clears **alpha only** (Xbox `D3DCLEAR` 0x80; target bits are per channel 0x10 R/0x20 G/0x40 B/0x80 A) and the host cleared all four. The channel bits now travel as host Clear flags (`D3D8_CLEAR_CHANNELS`) and a partial clear is a masked draw (`src/d3d/d3d8_clearmask.c`); clear rectangles are honoured the same way. Probably also the "screen goes dark when creatures shimmer" report (not reached in a scripted run).

18. Mouse look (real, not a fake stick): `sub_0025D520` (`player_apply_look`, integrates the look stick into `Player.yaw`/`pitch`, degrees) is wrapped in `recomp_manual.c`; after the original body runs, the raw mouse counts since last frame are added at 0.022 x sensitivity degrees per count (default 2.5), scaled by fov/default fov (scope), yaw grows to the left so mouse x is subtracted, yaw wrapped [0,360), pitch clamped +-60, only while the player has control. Path from pad to camera: `pad_poll_port` -> `g_pads` -> `pad_axis` -> `player_control_axis` (control scheme) -> `player_read_look_move` -> `player_apply_look`, all in `re/names.json`. Mouse buttons: left = R trigger (fire), right = L trigger, wheel up/down = D-pad left/right (FP's weapon change; `config/input_bindings.json`, `"mouse"` object for look/sensitivity/invert). F8 releases the cursor, a click recaptures; `RECOMP_MOUSE=0` disables capture. Toolkit side: `xboxrecomp/src/input/recomp_mouse.c` (raw input + capture from the removed e00a4eb, stick emulation dropped).

19. Settings crash (Audio/Video before the sub-menu showed; Controls on Accept): an unresolved indirect call to 0x002C3500 (from 0x00076C78), after which sub_00076810 read through a garbage pointer. Seeded in `config/seeds.json`.
20. Every pickup taken at load (story handguns x2, rifle/sniper at checkpoints, arcade matches starting with every weapon and power-up, bots scoring the bag over and over): `pickup_touch_test` (0x000C15B0) reaches its radius `jbe` (0x000C17D9) from two `comiss` sites, and the toolkit's join merge only knew `cmp`/`test`, so the jbe read the never-assigned `_flags` and the radius check never rejected anything. `_merge_flag_states` (`xboxrecomp/tools/recomp/translator.py`) now merges SSE compares (they snapshot `_fca`/`_fcb`); 48 such branches game-wide went from dead to real. Grep the generated C for `if (_flags /*`: 185 remain, each a branch that is never taken.
21. Mouse on mounted guns: move state 0x80 (`player_look_mounted`, 0x00258A20) turns the *object's* angles (object = character data +0xC14; its data +0x1C pitch, +0x24 yaw, arcs +0x34..+0x40), 0x40 (`player_look_seated`) turns the player relative to the object's heading. Both handled after the original body in `recomp_manual.c`.

22. Crash at a late checkpoint of the second level (access violation in `sub_0003E1E0` after `[ICALL] unresolved jump target 0x00000000`): an earlier unresolved indirect call to 0x00138F70 (from 0x00139087) returned 0. Seeded in `config/seeds.json`. The first `[ICALL] unresolved` line before a crash is usually the cause; `seed_from_log` also proposes `PsCreateSystemThreadEx` contexts, which are data: don't keep those.

23. Captain Ash flickering between the gunner seat and the ground in the second level (and getting run over): the AI vehicle update (`ai_vehicle_update`, 0x002A0500) skips the dismount action 0xD with `test al,0x10; jne` at 0x002A0C4D, a flag-state join. The toolkit's ZF-join fallback stored ZF in `_flags` and emitted every consumer as `if (_flags)`, so that `jne` was inverted and the AI ordered Ash out every third frame; with no exit animation for the gunner seat, `vehicle_dismount` put him at a nav point, and the next update seated him again. Consumers of a clear ZF now read `!_flags` (`xboxrecomp/tools/recomp/translator.py`, 6 branches game-wide). Chain in `re/names.json` (`vehicle_rider_action` -> `vehicle_rider_update` -> `vehicle_dismount`).

Replay tool additions: `--list-draws` prints fog states, raw vertex dwords and recorded vertex data; `REPLAY_ALL_CONSTANTS=1`, `REPLAY_TEX_DUMP=<id>` (writes `tex_<id>.bin`), `REPLAY_NO_CULL=1`, `REPLAY_NO_Z=1`; `RECOMP_D3D8_PS_SHOW=fograw`. `RECOMP_HLE_D3D8_ARRAY_CHECK=1` compares declarations with NV2A arrays (they agreed in level 1). `RECOMP_HLE_D3D8_ARRAY_TRACE=<stride>|1` (+ `_AFTER=<ms>`) prints declaration vs hardware arrays per draw. Replay: `--list-draws` shows each draw's program hash (`prog`, matches `RECOMP_D3D8_VS_DUMP=1` output), `REPLAY_SHOW_CONSTANTS=<first>[,<n>]`, `--skip-draw a-b`. Push dump reports hardware draw count (it matched intercepted draws).

24. Shimmering (cloaked) creatures darken the screen (user): fixed by 17, verified.

25. Faint brightness flicker on every map: FP swaps twice a frame, `Swap(D3DSWAP_BYPASSCOPY)` (0x2) then `Swap(FINISH)` (0x4); its swap callback colour-grades the world buffer (0x00204000) into the front buffer (0x00330000) between them. The host presented both, so the ungraded world reached the screen whenever the graded present missed the refresh. A BYPASSCOPY swap is no longer presented (`RECOMP_HLE_D3D8_PRESENT_BYPASS=1` restores it). Also: on frames where FP redraws nothing, the callback re-graded an already graded picture, because both frame buffers are one host back buffer; the host now keeps the picture of the buffer drawing moved away from (`hle_d3d8_fb_before_write`/`hle_d3d8_fb_kept`) and a frame-buffer texture is filled from it. Measured with 300 window grabs: 127 brightness jumps before, 0 after.
26. Uplink minimap (secondary mode) in the top-left corner / invisible hologram: FP draws the map into the screen's corner, `CopyRects` it out by rectangle into a 640x480 and a 128x128 texture, and clears the corner with boxed `Clear`s. The HLE read `CopyRects`'/`Clear`'s rectangle arguments *after* the XDK body, which reuses its argument slots, so the counts were 0: boxed clears became full clears and the copy shrank the whole screen into the texture. Arguments are now read first, and `CopyRects` copies rectangle-to-point (`xbox_D3D8CopyBackBufferRectToTexture`). Still read after the original (unaudited, working so far): `SelectVertexShader`, `Begin`, `SetVertexData4f`, `UpdateOverlay`, `GetBackBuffer2`. F11 now also traces the swaps it captures (`[TRACE]` lines incl. clear/copy rects).
27. Uplink start-up shimmer (blue square, then a square instead of a circle, map back in the corner): combiner gaps in `d3d8_combiners.c` -- the final combiner has its own constants (Xbox render states 43/44 -> host `D3DRS_PSFINALCOMBINERCONSTANT0/1`, emitted as `fc0`/`fc1`), stages share stage 0's C0/C1 unless `PS_COMBINERCOUNT` has UNIQUE_C0 (0x10<<8) / UNIQUE_C1 (0x100<<8), `AB/CD_BLUE_TO_ALPHA` output flags are implemented, and a stage's RGB writes land after the alpha portion reads its inputs. Plus a frame-buffer texture is re-copied whenever the frame buffer was drawn into since its last copy, not once a frame (`RECOMP_HLE_D3D8_FB_COPY_ONCE=1` for the old way): the shimmer's first bind was mid-way through building the corner, and the full-screen passes after the world sampled that.

28. Widescreen and HD/4K: FP has a real 16:9 mode (`sub_00023930` reads `XGetVideoFlags` bit 0, sets `D3DPRESENTFLAG_WIDESCREEN` and 16:9 aspect globals `0x4C0458`/`0x4C045C`). With `RECOMP_WIDESCREEN=1` its own `CreateDevice` failed (E_FAIL): the XDK's mode search (`sub_003DBE3D`, 0x3DC066) wants the widescreen bit 0x10000 in `AvSendTVEncoderOption(QUERY_AVPACK)`, where the real kernel ORs the EEPROM `XC_VIDEO` flags; now it is there. Toolkit display changes: `RECOMP_RES_SCALE` / `resolution_scale` takes a multiple or a height (`720p`, `1080p`, `1440p`, `4k`, `1080`); the scene is built at the output shape with square pixels (1920x1080 in widescreen, not an anamorphic 4:3 buffer stretched at present); the 2D squeeze is only for Hor+ (it boxed FP's graded frame into 4:3); frame-buffer textures (FP grades every frame through one) are made at the scene size with the guest's size kept for texel addressing (`xbox_D3D8SetTextureTexelSize`), without which any scale was a magnified 640x480 picture; the window opens 720 lines high when scaled; Alt+Enter = borderless fullscreen (SDL). The user's `~/.config/xboxrecomp/titles/45410066.conf` has `widescreen = 1`, `resolution_scale = 1080`. 4K holds ~59 fps here. Not scaled yet: the title's own offscreen render targets (R3 in `xboxrecomp/docs/technical/widescreen-and-resolution.md`).

## Linux port (Oct 2026)

Same sources, native x86-64 Linux build; the Windows build is unchanged in behaviour (verify on Windows after pulling: the shared files below were edited).
- **Renderer**: `src/d3d` is unchanged; on Linux the 61 D3D11 entry points it calls are implemented on Vulkan 1.3 in `xboxrecomp/src/d3d/vk/d3d11_vk.c` (dynamic rendering, all app images in GENERAL, full barrier between passes/transfers, per-frame upload arena for DYNAMIC Map(DISCARD), pipelines cached on the whole state + `~/.cache/xboxrecomp/vk_pipeline_cache.bin`). `vk/include/` supplies `<d3d11.h>/<dxgi.h>/<d3dcompiler.h>`. `D3DCompile` = shaderc (glslang HLSL), SPIR-V cached in `~/.cache/xboxrecomp/spirv`; VS inputs and PS inputs are linked by HLSL semantic (UserSemantic decorations, then stripped). Y flip = negative viewport; **no** front-face inversion (the toolkit doc's 4.4 was wrong: the negative viewport keeps D3D's on-screen winding; level 1 culls correctly). F9 overlay text via FreeType/fontconfig. `RECOMP_VK_VALIDATION=1`, `RECOMP_VK_LOG=1`, `RECOMP_VK_DEVICE=n`.
- **Platform** (`src/platform`): real `CONTEXT` + vectored exception handlers on sigaction (MMIO traps, watchpoints, fault reports all work), `host_sdl.c` (SDL window + event thread; backs `GetAsyncKeyState`, `GetForegroundWindow`, `GetClientRect`, `XInputGetState` via SDL GameController), SymFromAddr via dladdr (exe built with ENABLE_EXPORTS), futex `WaitOnAddress`, `posix_include/windows.h`. Audio: `src/hle/audio_output_sdl.c` (mixer with XAudio2's play-position contract). Mouse: SDL relative mode.
- **Bugs the port exposed** (real on both OSes): (1) `xbox_HeapAlloc`/`xbox_ContiguousAlloc` had no lock and two start-up guest threads raced (Linux: the title's 1 MB heap landed on live blocks -> fault at 0xFFFFFFF8); now one SRW lock. (2) clang fuses volatile `|=` into `or [mem], imm`, which no trap decoder knew (MSVC emits load/or/mov); `platform/mmio_decode.h` now decodes every RMW form (ALU r/imm, INC/DEC/NOT/NEG, XCHG/XADD/CMPXCHG, LOCK) and the APU, NV2A-interrupt and AC'97 handlers all go through it. (3) The POSIX file/path layer had fallen behind Windows: partition-device images (`Partition0..5.img` in `~/.local/share/xboxrecomp`), device-as-directory opens, FILE_CREATE collisions, root-relative opens, positioned pread/pwrite, plus case-insensitive path resolution (the disc has `UDATA` but `pak/`).
- Not ported: the RECOMP_SAMPLE profiler and exit tracing (use perf/gdb), XMV movies (as on Windows without ffmpeg), MSAA.

## Gotchas

- Line endings: both repos store LF and `.gitattributes` forces LF checkouts everywhere (`.bat`/`.cmd`/`.ps1` CRLF); `.editorconfig` matches. Python heredocs writing C with `\n` inside string literals have turned into real newlines here — check with `cat -A` after scripted edits.
- `rm -rf` of directories is blocked by the harness; leave scratch dirs (they're gitignored).
- Scripted runs create/modify saves in `game_files/UDATA/45410066` (a throwaway "bbbb…" profile exists).
- A Claude shell sees a `%APPDATA%\xboxrecomp\input_bindings.json` (stale) that the user's real profile doesn't have, and it wins over the one beside the exe: test runs that depend on the bindings need `RECOMP_INPUT_CONFIG=<repo>/build/input_bindings.json`.
- Don't commit game data, captures (`*.d3dcap`), dumps or generated C.
